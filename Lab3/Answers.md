### 1. Чим `class` відрізняється від `record`?
* **`class`** — посилальний тип для сутностей із власною ідентичністю (identity) та змінним станом. Порівняння за замовчуванням відбувається за посиланням.
* **`record`** — тип для незмінних (immutable) даних та value objects. Має автоматичну реалізацію порівняння за значенням (`Equals`, `==`), форматований `ToString()` і підтримку виразу `with`.

### 2. Що таке value equality?
**Value equality (рівність за значенням)** означає, що два об’єкти вважаються рівними, якщо збігаються значення всіх їхніх властивостей (`new Seat(3, 7) == new Seat(3, 7)` повертає `true`).

### 3. Чому основні entities у нашому проєкті залишилися `classes`?
Сутності (`Movie`, `Hall`, `Screening`, `Ticket`) мають унікальний ідентифікатор (`Id`) та життєвий цикл зі зміною стану (наприклад, зміна `ScreeningStatus` та кількості вільних місць у `Screening`).

### 4. Що таке value object?
**Value object** — це об’єкт предметної області без власного `Id`, який повністю визначається набором своїх атрибутів (у нашому проєкті — `record Seat(int Row, int Number)`).

### 5. Що робить `required`?
Модифікатор **`required`** зобов’язує ініціалізувати властивість під час створення об’єкта в ініціалізаторі `{ ... }`, інакше виникне помилка компіляції.

### 6. Чим `init` відрізняється від `set`?
Аксесор **`init`** дозволяє встановити значення лише під час створення об’єкта (у конструкторі або ініціалізаторі), після чого властивість стає доступною тільки для читання, тоді як `set` дозволяє змінювати її будь-коли.

### 7. Що означає `string?`?
Тип **`string?`** при увімкнених Nullable Reference Types явно вказує, що властивість або змінна може містити `null` (значення є необов’язковим).

### 8. Що таке null-state analysis?
**Null-state analysis** — це статичний аналіз компілятора C#, який перевіряє стан змінних на можливий `null` і попереджає про потенційний `NullReferenceException` ще до запуску програми.

### 9. Для чого використовують `enum`?
Перерахування **`enum`** використовують для опису фіксованого набору іменованих станів (наприклад, `ScreeningStatus`), що робить код безпечним і зрозумілим.

### 10. Що таке pattern matching?
**Pattern matching (зіставлення зі зразком)** — це механізм C# для перевірки форми, типу, значень або властивостей даних за шаблонами у конструкціях `is` та `switch`.

### 11. Що таке relational pattern?
**Relational pattern** дозволяє порівнювати значення з константами за допомогою `<`, `<=`, `>`, `>=` (наприклад, визначення категорії фільму `Short`, `Standard`, `Long` за тривалістю).

### 12. Що таке property pattern?
**Property pattern** дозволяє перевіряти значення властивостей об’єкта у фігурних дужках: `{ Status: ScreeningStatus.SalesOpen, AvailableSeats: 0 } => "SoldOut"`.

### 13. Коли `switch expression` зручніший за `switch statement`?
**`switch expression`** зручніший, коли потрібно обчислити й повернути одне значення: він компактніший, не потребує `break`/`return` у кожній гілці та перевіряє повноту покриття варіантів.
